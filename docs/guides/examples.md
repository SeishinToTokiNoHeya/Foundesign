# 예제 반영 기준

기능 개발은 사용자가 기능을 발견하고 조작할 수 있는 예제까지 포함합니다.
새 기능이나 사용법 변경은 같은 변경 묶음에서 예제에 반영합니다. 기존 예제로 충분하면 그 예제로 확인합니다.
주석만 바꾸는 작업은 예제의 API 사용과 설명이 맞는지 확인합니다.

## 어디에 추가하는가

- 컴포넌트: `Example/Example/Pages/Component/<기능>ExamplePage.swift`
- 토큰·테마: `Example/Example/Pages/Foundation/<기능>ExamplePage.swift`
- 탐색 등록: `Example/Example/Pages/FoundationPages.swift`

이름과 달리 `FoundationPages.swift`에는 `FoundationPages`와 `ComponentPages`가 모두 있습니다.
새 페이지는 해당 enum case, `title`, `navigationDestination`의 switch에 모두 추가합니다.
`ContentView`의 목록은 `allCases`를 사용하므로 등록된 페이지가 목록에 노출됩니다.
현재 Xcode 프로젝트는 동기화 폴더를 사용하지만 최종 빌드에서 새 파일 포함 여부를 확인합니다.

기능당 별도 페이지를 강제하지는 않습니다. DatePicker처럼 WheelPicker 페이지에서 자연스럽게
함께 설명할 수 있으면 그 페이지를 확장합니다.

## 무엇을 보여 주는가

| 확인 대상 | 예제에 반영할 내용 |
| --- | --- |
| 기본 사용 | 기본 속성으로 바로 실행 가능한 구성 |
| 주요 변형 | 크기·톤·스타일 등 새로 추가하거나 변경한 옵션 |
| 상태 | 선택·부분 선택·펼침·비활성 등 해당 기능의 상태 |
| 경계 조건 | 긴 라벨, 좁은 폭, 빈 값, 월말·윤년 등 변경과 관련된 상황 |
| 상태 반영 | 현재 선택값이나 액션 결과를 확인할 수 있는 표시 |
| 플랫폼·테마 | 영향이 있는 경우 iOS/macOS, 밝은·어두운 모드, 커스텀 테마 |

모든 조합을 화면에 무작정 늘리지 않습니다. 새 계약과 회귀 위험을 보여 주는 대표 사례를 선택합니다.
소비자처럼 `import Foundesign`과 공개 API만 사용하고, 라이브러리 로직을 예제에 복제하지 않습니다.
Preview만으로 실제 탐색 가능한 예제를 대체하지 않습니다.
