# 현재 개발 단계와 리뷰 정책

현재는 디자인 시스템의 기능·공개 API·디자인 구성과 사용 예제를 완성하는 데 집중합니다.
접근성과 테스트 코드는 디자인 시스템이 어느 정도 완성된 뒤 별도 작업으로 일괄 진행합니다.
적용 범위는 Foundation, Component, Example을 포함한 저장소 전체입니다.

## 지금의 작업 범위

- 작업 범위와 공통 완료 조건은 [AGENTS.md](../../AGENTS.md)를 따릅니다.
- 접근성 유예는 VoiceOver, 접근성 속성·포커스, 키보드 탐색, Dynamic Type, 대비·동작 줄이기 등의 전용 구현·검증을 포함합니다.
- 테스트 유예는 단위·통합·UI·스냅샷 테스트 코드, 커버리지 목표, 테스트 프레임워크·타깃 도입을 포함합니다.
- 위 두 항목을 일반 기능 개발이나 버그 수정의 완료 조건으로 추가하지 않습니다. 기존 구현은 유지합니다.
- 빌드, 문서 검사, 예제의 기본 동작 확인은 [검증 가이드](validation.md)에 따라 변경 범위에 맞게 수행합니다.

## 보조 도구와 검증을 추가하는 기준

- 문서화·AI 활용·배포·검증 요청을 별도 스크립트나 도구를 만들어 달라는 요청으로 해석하지 않습니다.
- 기존 도구의 공식 명령과 기본 설정을 먼저 사용합니다. CI에는 필요한 명령의 짧은 조합만 두며,
  제거한 스크립트의 파싱·변환·검사 로직을 YAML이나 다른 언어로 옮기지 않습니다.
- 보조 스크립트는 사용자가 명시적으로 요청했거나, 현재 반복되는 작업을 기본 기능으로 처리할 수
  없는 구체적인 이유가 있을 때만 검토합니다. 먼저 부가 기능을 줄일 수 있는지 확인하고,
  도입이 필요하다면 해결할 문제·기본 기능으로 부족한 이유·유지보수 범위를 설명합니다.
- 구현 전에 이 기준을 적용합니다. 사용자가 에이전트의 계획을 승인했더라도 기존의 단순화
  원칙을 무시해도 된다고 판단하지 않습니다. 사용자의 명시적인 범위 변경은 따릅니다.
- 현재 테스트 코드 유예 정책을 유지합니다. 테스트를 별도로 요청받더라도 실제 동작과 실패 조건을
  확인하는 최소 사례부터 작성하고, 구현을 그대로 되풀이하는 검사나 문구·파일 목록이 바뀌지 않았는지만
  확인하는 테스트는 피합니다. 관련 없는 플랫폼이나 입력 조합까지 검증 범위를 늘리지 않습니다.
- 변경별 검증의 선택과 종료 기준은 [검증 가이드](validation.md)를 따릅니다. 검증을 위해 제품 구조나
  의존성을 늘리지 않고, 기존 검증을 새 도구로 중복 구현하지 않습니다.

## GitHub Codex 리뷰

리뷰 범위와 언어는 루트 [AGENTS.md](../../AGENTS.md)의 `Code Review Rules`를 따릅니다.
GitHub에서 요청하는 Codex 리뷰와 자동 리뷰에 모두 적용합니다.

- 제외한 접근성·테스트 코드 사항은 인라인 지적, 리뷰 요약, 개선 제안, TODO, 반복적인 유예 안내에도 넣지 않습니다.
- 실제 기능 오류를 발견했다면 테스트 부재 대신 문제가 발생하는 조건, 구현 원인, 사용자 영향을 설명합니다.

## 후속 단계로 전환할 때

접근성 또는 테스트 코드 작업을 별도로 요청받으면 해당 요청 범위에서 진행합니다.
일반 기능 개발 요청만으로 유예 정책이 종료되었다고 판단하지 않습니다.
전체 개발 정책을 전환할 때는 이 문서와 루트 AGENTS의 관련 규칙을 함께 갱신합니다.
