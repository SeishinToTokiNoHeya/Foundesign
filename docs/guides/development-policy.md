# 현재 개발 단계와 리뷰 정책

현재는 디자인 시스템의 기능·공개 API·디자인 구성과 사용 예제를 완성하는 데 집중합니다.
접근성과 테스트 코드는 디자인 시스템이 어느 정도 완성된 뒤 별도 작업으로 일괄 진행합니다.
적용 범위는 Foundation, Component, Example을 포함한 저장소 전체입니다.

## 지금의 기능 개발 범위

| 항목 | 현재 정책 |
| --- | --- |
| 기능 구현·공개 API·DocC 주석 | 변경한 기능에 맞게 함께 작성 |
| 실행 가능한 예제·탐색 등록 | 기능 추가·변경 시 함께 반영 |
| 패키지·Example 빌드, 문서 링크·DocC 검사 | 변경 범위에 맞게 실행 |
| 예제의 기본 동작 확인 | 변경한 기능을 조작하고 결과 확인 |
| 접근성 전용 구현·검증 | 후속 일괄 작업으로 유예 |
| 테스트 코드·테스트 타깃·테스트 기반 도입 | 후속 일괄 작업으로 유예 |

접근성 유예에는 VoiceOver, 접근성 라벨·값·힌트·트레이트, 포커스와 접근성용 키보드 탐색,
Dynamic Type 대응, 대비·동작 줄이기 등 접근성 요구에 대한 별도 구현과 검증이 포함됩니다.
현재 기능의 완료 조건으로 접근성 체크리스트나 감사를 추가하지 않습니다.

테스트 코드 유예에는 단위·통합·UI·스냅샷 테스트, 커버리지 목표, 테스트 프레임워크와
타깃 도입이 포함됩니다. 일반 기능 개발이나 버그 수정에 테스트 코드 추가·보강을 요구하지 않습니다.
현재 패키지에는 테스트 타깃이 없으므로 `swift test`를 필수 검증으로 기재하지 않습니다.

기존 구현은 유지하고 변경 기능에 필요한 범위만 작업합니다. 빌드, 문서 검사와 예제에서의
기본 동작 확인은 계속 수행하며 실제로 확인한 결과만 기록합니다.
접근성 지원이나 테스트 수행을 확인하지 않았다면 완료했다고 설명하지 않습니다.

## GitHub Codex 리뷰

루트 [AGENTS.md](../../AGENTS.md)의 `Code Review Rules`가 저장소 공통 리뷰 지침입니다.
GitHub에서 요청하는 Codex 리뷰와 자동 리뷰에 다음 정책을 적용합니다.

- 접근성 구현·지원 수준·미비점·개선 제안은 리뷰하지 않습니다.
- 테스트 코드의 유무·추가 필요성·커버리지·구조·품질·테스트 기반은 리뷰하지 않습니다.
- 위 두 항목은 인라인 지적, 리뷰 요약, 개선 제안, TODO, 반복적인 유예 안내에도 넣지 않습니다.
- 그 외 변경한 기능의 실제 오류, 빌드 문제, 공개 API 호환성, 문서·예제와 구현의 불일치를 검토합니다.
- 실제 기능 오류를 발견했다면 테스트 부재 대신 문제가 발생하는 조건, 구현 원인, 사용자 영향을 설명합니다.
- 리뷰 제목·본문·인라인 코멘트·요약·수정 제안은 한국어로 작성합니다. 심볼·파일 경로·코드·도구 출력의 원문은 유지합니다.

공식 OpenAI 문서도 저장소 전체의 리뷰 규칙을 루트 `AGENTS.md`에 두도록 안내합니다.
이 파일과 연결된 가이드를 GitHub 저장소에 반영한 뒤 리뷰를 요청합니다.
[GitHub Codex 리뷰 지침 공식 안내](https://learn.chatgpt.com/docs/third-party/github#customize-what-codex-reviews).

## 후속 단계로 전환할 때

접근성 또는 테스트 코드 작업을 별도로 요청받으면 해당 요청 범위에서 진행합니다.
일반 기능 개발 요청만으로 유예 정책이 종료되었다고 판단하지 않습니다.
전체 개발 정책을 전환할 때는 이 문서, 루트 AGENTS의 리뷰 규칙과 관련 개발·검증 가이드를 함께 갱신합니다.
