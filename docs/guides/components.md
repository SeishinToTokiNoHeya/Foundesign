# 디자인 컴포넌트 개발 규칙

[현재 개발 정책](development-policy.md)에 따라 접근성 전용 작업과 테스트 코드 작성은
후속 일괄 작업으로 유예합니다. 현재 기능의 완료 조건에 두 항목을 추가하지 않습니다.

## 설계 전에 결정할 계약

- 사용자가 해결할 작업과 기존 컴포넌트로 조합 가능한 범위를 먼저 확인합니다.
- 상태의 소유자, 초기값, 입력 제약, 비활성 상태, 콜백과 Binding 변경 시점을 정합니다.
- iOS·macOS에서 동일한 공개 API를 제공하고 차이가 있다면 주석과 사용 안내에 기록합니다.
- 새 공개 이름은 기존 `Foundesign…` 패턴을 우선합니다. 기존 `AlertDialog…`, `ContentFog`, `FoundedCheck…` 이름을 문서 작업만으로 바꾸지 않습니다.

## 파일과 API

`Sources/FoundesignComponent/<기능>/`에 기능을 모으고 필요할 때 아래 구분을 사용합니다.

| 위치 | 넣을 내용 |
| --- | --- |
| `Group/` | 여러 요소를 조합하는 컨테이너, 그룹, 레이아웃 |
| `Item/` | 그룹을 이루는 항목과 작은 뷰 |
| `Property/` | 크기·톤·상태 값, 환경 설정 |
| `Style/` | SwiftUI 스타일 구현 |
| `Presentation/`, `Scroll/` | 표시·스크롤 조율과 플랫폼별 구현 |

- 표준 `Button`, `Toggle`, `Binding`, `ButtonStyle` 등의 역할에 맞춰 API를 구성합니다.
- 스타일은 명시적인 속성값으로 표현하고 그룹 공통 설정은 환경을 활용합니다. 명시값과 상속값의 우선순위를 문서화합니다.
- 외부 사용에 필요한 선언만 공개합니다. builder 결과형처럼 공개해야 하는 구현 보조형은 용도를 명시합니다.
- 프로젝트의 2칸 들여쓰기와 인접 파일의 네이밍을 따릅니다.

## 테마·상태·플랫폼

- 색상·폰트·간격·모서리는 `theme.color`, `theme.typography`, `theme.spacing`, `theme.radius`에서 가져옵니다.
- 의미별 토큰을 우선 사용합니다. 컴포넌트 안에서 브랜드 팔레트의 특정 단계나 색상 리터럴을 직접 선택하지 않습니다.
- 선 두께, 애니메이션 시간, 기하 계산 등 토큰이 아닌 값은 필요한 근거를 가까운 `//`에 남깁니다. 일회성 값을 모두 토큰으로 만들지는 않습니다.
- `.disabled`와 상위 환경을 존중합니다. 긴 라벨과 좁은 폭에서 기능의 기본 배치와 동작을 확인합니다.
- 상태 보정이나 콜백 중복 방지는 공통 동작으로 관리하고 플랫폼 어댑터에 서로 다른 계약을 만들지 않습니다.
- UIKit/AppKit 브리지는 해당 플랫폼 폴더에 격리합니다. 공통 코드는 한 플랫폼만 확인하고 호환성을 단정하지 않습니다.

## 코드에서 특히 주의할 기존 계약

- AccordionItem의 `action`에서 호출자가 펼침 상태를 바꿉니다. 항목이 자동으로 토글한다고 가정하지 않습니다.
- Checkbox의 명시적 `property`가 환경 속성보다 우선하며, 빈 `sources`는 비활성 미선택 상태입니다.
- WheelPickerColumn은 고유한 값이 필요하고 스크롤 종료 후 선택을 확정합니다. 목록 밖 selection의 표시와 실제 Binding은 다를 수 있습니다.
- DatePicker는 시간대를 반영해 연도 범위·월말·날짜 시작 시각을 보정합니다.
- AlertDialog는 표시 상태와 닫힘 전환을 관리합니다. 버튼 액션과 `onDismiss`의 호출 시점을 구분합니다.

정확한 최신 계약은 각 선언의 `///`를 확인합니다. 이 목록은 확인할 위치를 알려 주는 요약입니다.

## 기능 완료 기준

1. 구현과 영향을 받는 공개 API 주석을 함께 수정합니다.
2. 새 기능이면 모듈 DocC의 Topics와 사용 안내에 연결하고, 변경이면 기존 안내를 갱신합니다.
3. [예제 기준](examples.md)에 따라 기능을 실행·조작할 수 있는 예제를 반영합니다. 파일만 추가하고 탐색 등록을 빠뜨리지 않습니다.
4. [기능 색인](../ai/catalog.json)에 소스·문서·예제의 경로를 반영합니다.
5. [검증](validation.md)에 따라 빌드·문서 검사와 변경 기능의 기본 동작 확인을 수행하고 결과를 기록합니다.

내부 수정으로 사용 예제가 달라지지 않는다면 기존 예제를 확인하고 변경 불필요 이유를 결과에 적습니다.
